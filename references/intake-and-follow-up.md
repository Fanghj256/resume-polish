# 信息引导与补充提问

目标是让用户逐步提供能写进简历的真实证据，不要求用户先懂简历写法，也不让用户填一张冗长问卷。

## 1. 根据起点进入

**已经有旧简历和岗位：**先读两者，整理已知事实与匹配点。直接问最影响该岗位的缺口，不重新索要姓名、联系方式、时间和已写清的职责。

**有经历，但没有旧简历：**允许先口述一段，不要求按 STAR、表格或固定格式输入。可以这样引导：

> 不用先整理成简历。你可以直接说最近做过的一两件事：当时要解决什么问题、你亲手做了哪些环节、最后交付了什么。我先帮你梳理，再问缺的部分。

**连经历从哪里说起都不确定：**从最近或最相关的一件工作、实习、课程、个人项目、志愿活动开始。问一个具体事件，不让用户抽象总结“核心竞争力”。资历少不意味着必须编写职业成果。

**没有具体岗位：**先问想投哪类工作，必要时给 2–3 个与已知经历有关的方向供选择。用户只要通用简历时继续，不强求一个不存在的 HC。

**招聘链接读不到或内容不完整：**说明具体缺了哪段，邀请补岗位正文或截图。已看到的部分可先使用；不要靠岗位名称猜一套职责并当成招聘原文。

## 2. 建立缺口判断

在工作草稿中维护这张小表；用户需要时再展示，不能用做表代替写简历。

| 岗位的关键工作 | 用户已有证据 | 状态 | 下一步 |
| --- | --- | --- | --- |
| 对应 JD 中的一项实际职责 | 原稿/对话中可定位的事实 | 已确认 / 缺细节 / 未提及 / 明确未做过 | 直接写 / 追问 / 寻找可迁移证据 / 不写 |

- **已确认：**直接写，不能为了“严谨”再问一遍。
- **缺细节：**有相关经历，但个人贡献、判断或交付不清楚。优先追问这类信息，通常收益最高。
- **未提及：**不能推断没做过；用开放问题问是否有相关例子。
- **明确未做过：**不反复诱导用户承认。可查找其他项目中相近的真实能力，同时保留岗位匹配的实际限制。
- **前后冲突：**日期、职责或数字冲突时，指出两种表述，只问确认哪一种，不替用户选更漂亮的一种。

## 3. 每轮问最值得补的 1–3 件事

按“岗位重要性 × 现有证据缺口”排序。通常优先个人贡献、关键动作与判断、成果/交付，而非兴趣爱好或不影响岗位的琐碎信息。将同一项目的紧密相关问题放在一起，别一条消息塞十几个问号。

问题应包含：**已知背景 + 一个具体缺口 + 容易回答的入口**。必要时说明答案为什么有用，避免空泛的“还有什么要补充吗”。

例如：

> 你写到参与了活动运营。这个岗位比较看重独立推进，你具体负责哪些环节？从你亲自做的一件事说起就行；如果只是协助，也按实际情况告诉我。

> 你提到做过产品改版。你当时根据什么判断先改哪一块，最后上线了什么？没有增长数据也没关系，可以说交付物和实际收到的反馈。

> 这份岗位说明需要服务创业项目。你之前有没有接触、筛选或持续跟进项目的经历？有就讲一个例子；没有的话，我会看你其他经历能证明哪些相关能力。

不要问：“我给你写成建立评分机制、促成融资、提升转化率可以吗？”这会把未确认的成果塞给用户。

## 4. 按岗位选择追问方向

只选本轮最相关、且原稿没有回答的方向；以下不是每次必须问完的清单。

| 方向 | 可用的回忆入口 |
| --- | --- |
| 产品 / 技术产品 | 谁遇到什么问题？你如何验证需求、做取舍？你交付了哪些方案、原型、版本或评测？ |
| 运营 / 增长 | 面向谁、通过什么渠道？你具体策划或执行什么？有哪些可确认的数据、反馈或迭代？ |
| 社区 / 活动 / 初创营 | 选题、招募、筛选、物料、嘉宾、现场、后续跟进中，你实际做了哪些？举一个最能说明你独立推进或协调问题的例子。 |
| 项目管理 | 目标、时限和合作方是什么？出现了什么具体风险或分歧，你怎么处理，最终交付到什么状态？ |
| 客户 / 商业 | 客户的问题是什么？你如何界定需求、提出方案、交付与跟进？哪些反馈或结果有依据？ |
| 应届 / 转行 | 哪次课程、实习、社团、个人项目或原岗位工作能证明目标能力？你独立完成了什么，留下了哪些作品？ |

## 5. 数字、记忆不完整和回答过短

- 数字不清楚时允许用户说大概范围，但只能记录其确认的精度；不自行估算。“记不清”不是写“100+”的依据。
- 没有结果指标时问交付物、服务对象反馈、是否实际使用、后续动作；这些同样能构成证据，不用逼出一个增长百分比。
- 用户说“全流程都做过”，可列出当前项目最相关的几个环节让其补一个具体例子；此前已经逐项列举、用户明确确认过的环节直接使用。
- 用户回复“都做过”只覆盖紧接着问题里的具体事项。可写已确认的事项，不顺带发明规模、方法、成果、头衔。
- 用户说“你发挥”“包装一下”，优化表达与结构；仍未确认的事实不写。可解释“我先按现有事实写，缺少的数据先不加”。
- 用户没有更多时间或资料时，用已确认事实完成可用版本，并简短指出最值得以后补的一项；不连续追问阻碍交付。

## 6. 把回答真正写回成品

收到回答后：

1. 提取新增的责任、动作、判断、规模、成果与不确定性，标明来源是本次回答。
2. 更新对应项目，而不是把原话作为一段孤立“补充说明”贴在简历末尾。
3. 检查是否会重复核心优势或工作经历，必要时一处展开、其他处概括。
4. 重新检查岗位匹配与单页容量。还有关键缺口再问下一轮；信息已足以写出有依据的简历时进入排版。
5. 用一句话让用户知道已采用哪些补充。只有冲突、敏感措辞或实质改变含义时才需要再次确认，不默认每条都走审批。

## 7. 完成判断

能否读出目标岗位、最相关项目、候选人的实际贡献，以及有依据的结果或交付？关键联系方式与时间线是否齐全？若是，则完成排版导出；若否，优先问那个阻碍理解的问题。不能把“页面没填满”变成无限问答，也不能在缺少事实时直接扩写一页漂亮的虚构经历。
